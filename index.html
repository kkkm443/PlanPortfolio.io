링글 공모전 본선 진출

01 · 문제

전체 설문 응답 91명 중 재직 경험이 있는 69명을 따로 살폈습니다. 이 중 40명(58.0%)은 업무 자료 기반 롤플레잉의 필요성을, 49명(71.0%)은 교정 리포트의 중요도를 4–5점으로 평가했습니다.

02 · 접근 방법

조사 결과와 일정 안에 구현할 수 있는 범위를 함께 검토해 발표 대본 자동 작성은 제외하고, 업무 자료 기반 질의응답 연습을 우선 기능으로 정했습니다. 상대 프로필과 대화 맥락, 통화 후 피드백을 기능 흐름에 반영했습니다.

03 · 담당한 작업

4인 팀에서 시장·사용자 조사와 AI 기능 제안에 참여했습니다. 기능 정의서, 플로우차트, 와이어프레임을 작성하고 웹 프로토타입을 구현했습니다. 학습 진입부터 통화 후 피드백까지 화면별 기능과 이동 흐름을 정리했습니다.

04 · 결과와 배운 점

업무 자료 연습과 피드백 기능을 화면 흐름으로 구체화한 웹 MVP를 팀과 공유했습니다. 모델 학습을 기간 내 구현하기 어렵다는 점을 설명해 후속 과제로 두고, 먼저 완성 가능한 프로토타입에 집중하기로 합의했습니다. 팀은 링글 서비스 기획 공모전 본선에 진출했습니다.

DLL 구현 · 품질 개선 중

01 · 문제

로컬 AI로 게임 대사를 번역하려 했지만, 기존 플러그인의 호출 방법을 알 수 없었습니다. 반복 번역과 미완료 요청도 처리해야 했습니다.

02 · 접근 방법

사용하던 플러그인의 호출 방식은 유지하고, 번역을 처리하는 DLL을 교체했습니다. 같은 원문의 번역은 재사용하고, 미완료 작업은 다음 실행 때 이어서 처리하도록 했습니다.

03 · 담당한 작업

Visual Studio 개발 도구로 export 목록을 확인하고 Ghidra로 함수 포인터 호출을 분석했습니다. 기존 ordinal을 유지한 ezTransXP.dll을 구현해 Ollama와 연결했습니다. AI·기존 번역 캐시, 작업 큐, 입력 분류를 추가하고 AI 통신 오류가 나면 기존 번역 결과를 표시하도록 했습니다.

04 · 결과와 배운 점

기존 플러그인에서 로컬 AI 번역을 사용할 수 있게 됐습니다. 글자 깨짐, 프롬프트 노출, 문장 잘림을 수정했습니다. 문장 연결과 호칭 보정 규칙을 추가한 뒤 오역이 늘어, 추가 프롬프트를 줄이고 생성 설정을 이전 기준으로 되돌렸습니다. 이름 대응표 노출과 인물 간 관계와 호칭 오류도 보완했습니다. 이 과정에서 규칙을 추가할 때는 기존 캐시뿐 아니라 새로 생성되는 번역 결과도 비교해야 한다는 점을 배웠습니다.

  • 호출 방식 확인export 목록과 디컴파일 결과에서 플러그인의 진입점과 간접 호출 구조를 확인했습니다. 이를 바탕으로 기존 ordinal을 유지한 대체 DLL을 만들었습니다.

  • 추가한 규칙 재검토문장 연결과 호칭 보정 규칙을 추가한 뒤 새 번역에서 오역이 늘어났습니다. 이후에는 규칙을 추가할 때 원문과 결과를 비교하며 확인했습니다.
